[VERMEIL] Visual 2.5D - CUARENTENA DE MODELOS 3D
================================================

Estado: V7 / modo "Terrain Tags only".

QUE HAY AQUI
------------
Archivos del subsistema 3D (meshes importados, fisica de modelos, objetos del
editor Geometry, mesh nativo) aislados de la carga. La extension .off NO se
carga: PluginManager filtra por ".rb" (Dir.all es recursivo, asi que mover a
subcarpeta no basta; el sufijo .off es lo que desactiva).

  026_NDSGeometryObjects.off           Objetos del editor (cubos/planos quads 3D) + mesh region
  028_GeometryCollisionAuthority.off   Autoridad de colision de Geometry/modelos
  029_ModelPhysics.off                 Fisica de modelos: ModelPhysicsWorld + gate de Game_Player
  030_ModelStream.off                  Stream diferido de meshes Model Studio (.v25m)
  039_V25BillboardModelCollisionFix.off Colision billboard/modelo (.v25c preload en setup)
  046_V25NextNativeMeshBridge.off      Bridge de mesh nativo mkxp-z (inerte en stock Sky)

POR QUE
-------
El 2.5D cargaba lento. Se aísla todo lo 3D para dejar un unico camino de alturas:
los Terrain Tags NDS (IDs 19-37) asignados en cada tileset. Sin .v25r/.v25m/.v25c
en el proyecto, estos sistemas ya eran no-op; la cuarentena elimina sus hooks,
prepends y tama de setup/update para que la carga vaya directa al nucleo 2.5D.

COMO REACTIVAR (cuando se quiera probar 3D otra vez)
----------------------------------------------------
1] Renombra aqui los archivos de .off a .rb (vuelven a cargarse en orden por su prefijo).
2] En 001_Settings.rb:
     NDS_GEOMETRY_OBJECTS_ENABLED  -> true     (dibuja objetos del editor)
     SURFACE_GEOMETRY_RUNTIME_FILES -> true    (permite .v25r sobrescribir la superficie)
   SURFACE_GEOMETRY_ENABLED se queda en true (es tambien la ruta de Terrain Tags).
3] Guarda el mapa con Geometry si quieres que el overlay .v25r mande.

NOTA
----
El archivo Data/VERMEIL_GEOMETRY_V4/Map079.v25d es solo metadata de editor
(preview angle/yaw/zoom, 0 celdas/objetos/meshes): no afecta al runtime actual.
