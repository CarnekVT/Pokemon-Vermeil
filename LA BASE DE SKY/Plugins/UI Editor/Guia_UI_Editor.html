1. Instalacion y Requisitos

Antes de usar el plugin, asegurate de cumplir los siguientes requisitos obligatorios:

⛔ Requisitos obligatorios El plugin solo funcionara si se cumplen estas tres condiciones:
  1. Compatible unicamente con La Base Del Sky 1.2.0 (y versiones posteriores).
  2. Solo puede ser usado en Modo Debug ($DEBUG = true).
  3. Tener los scripts fuera del editor de scripts de RPG Maker (no obligatorio, pero facilita al editor encontrar la ruta exacta del archivo Ruby donde se crea la UI).

2. Explicacion General de Uso

El plugin permite editar sobre la marcha las UI por defecto (y las que hayas especificado) de tu proyecto, sin necesidad de cerrar el juego ni modificar codigo manualmente cada vez.

Registrar una UI para editar

Ve a la carpeta UI Editor y abre el archivo 000_Settings.rb. En el array UI_EDITABLE_CLASS, añade la clase de tu scene/UI:

UI_EDITABLE_CLASS = [
  "UI::MoveReminderVisuals", "UI::BaseVisuals",
  "PokemonParty_Scene", "PokemonPokedex_Scene", "PokemonBag_Scene",
  "PokemonSummary_Scene", "PokemonLoad_Scene", "PokemonPokedexMenu_Scene",
  "PokemonPokedexInfo_Scene", "PokemonTrainerCard_Scene",
  "PokemonRegionMap_Scene",
  "Battle::Scene::MenuBase", "ItemStorage_Scene", "PokemonStorageScene",
  "PokemonReadyMenu_Scene", "MoveRelearner_Scene"
  # Añade tu propia clase aqui
]

Activar el editor en la scene

Una vez instalado el plugin y activado el modo debug, entra a la scene que quieres editar y presiona F5. El editor se inicializara automaticamente.

Instalacion manual para UIs personalizadas

Si una UI personalizada tiene problemas al inicializar el editor, deberás "inyectar" el editor manualmente dentro del ciclo update / pbUpdate de tu clase. Un ejemplo con la UI de Recuerda Movimientos:

class UI::MoveReminderVisuals
  alias_method :ui_editor_alias_update_input, :update_input

  # Añadir el bloque if en el update/pbUpdate/Main_loop
  # o donde se manejen los inputs de la UI
  def update_input
    # Puedes cambiar F6 por otra tecla de tu preferencia
    if Input.triggerex?(:F6) && $DEBUG && !UI_Editor::ControlEditor.active?
      UI_Editor_Helper.call(self) # Llama al editor para procesar los datos
    end
    ui_editor_alias_update_input()
  end
end
💡 Nota sobre la tecla de activacion Puedes cambiar :F6 por cualquier otra tecla si hay conflictos. Las teclas del editor son personalizables desde Settings_UI_Editor::KEYS dentro de 000_Settings.rb.

4. Modo Sprites

Al abrir el editor en una escena veras entre uno, dos y tres modos disponibles: SPRITES CONST IVARS

El Modo Sprite permite editar todos los objetos visuales que heredan de la clase Sprite o que son muy similares. Un sprite es un contenedor de un bitmap: carga una imagen (boton, background, icono, Pokemon, etc.).

El editor también encasilla como "visuales" a todos aquellos objetos que respondan a un metodo (x, y, z), tengan un bitmap definido (o contents), sean visible y no sean un viewport.

💡 ¿Que puedes modificar en modo Sprite? Los sprites responden a métodos de transformación como zoom, opacity, angulo y visibilidad, ademas de su posicion (x, y) y z (profundidad). El editor permite cambiar todo esto sin tocar el codigo directamente.

Controles del Modo Sprite

Tecla / ComboAccion
← → ↑ ↓Modifican la posicion X/Y del objeto (o OX/OY en objetos Plane)
Ctrl + movimientoAplica un step de valor +10 a cada comando del editor
Shift + movimientoAplica una grilla de 8 px para movimiento mas rapido
Tab + 1Aumenta en 1 el valor Z (profundidad)
Tab + 2Disminuye en 1 el valor Z (profundidad)
DAumenta la opacidad del objeto (rango 0…255)
ADisminuye la opacidad del objeto (rango 0…255)

SDisminuye el zoom del objeto (si responde a este)

⚠️ Personalizacion de teclas Puedes cambiar todas estas teclas en la clase Settings_UI_Editor::KEYS dentro de 000_Settings.rb.

5. Modo Internals (Objetos Internos)

Hay casos donde puedes mover objetos pero a su vez, estos tienen otros objetos dentro. Por ejemplo, en el panel de la party moverias todo el panel — lo cual es correcto. Sin embargo, ¿que pasa si solo quieres mover el icono de la Poke Ball? Ahi entran los Internals (o Internos).

✅ ¿Que son los Internals? Son objetos que nacen de un objeto padre (el panel) y estan ligados a el. El editor permite navegar entre el objeto principal y sus objetos hijos pulsando F, accediendo a objetos como el icono de la Poke Ball, el icono del Pokemon, etc. Cada uno puede modificarse de manera independiente del objeto padre.

Posicion relativa al padre

La posicion del internal es relativa al objeto padre. Si mueves un internal y despues mueves al objeto padre, el internal volvera a su posicion original relativa respecto a la nueva posicion del padre.

Como aparecen los internals en el historial

Al hacer el reporte para guardar cambios, los internals apareceran bajo el siguiente formato en el Log:

# El internal se accede mediante instance_variable_get desde el objeto padre
sprite = @sprites['pokemon5'].instance_variable_get(:@panelbgsprite).x += 20

Problema importante con los Internals

El objeto padre generalmente llama a su propio metodo de refresh y borra todo el reposicionamiento hecho al internal. Por eso, al trabajar con internals debes colocar su delta (+= o -=) no en el pbStartScene ni en el initialize.

⚠️ Donde colocar los deltas de los Internals
  • Prueba hacerlo al final del refresh de la scene.
  • O modifica directamente la instancia en la clase del objeto padre sumandole los deltas:
# Correcto: modificar directamente la instancia en la clase padre
@panelbgsprite.x += 20

6. Modo Const e IVARS — ¿Por que existen?

Aunque con el modo Sprites puedes resolver un gran porcentaje de los problemas de posicionamiento, debido a como funciona Essentials te toparas con barreras de cosas que no puedes mover.

Por ejemplo, si en el modo Sprite vas a un objeto llamado Overlay, veras que se iluminan varias cosas a la vez (textos, iconos, imagenes, etc.). Si quisieras mover solo un texto, verias que se mueve todo lo iluminado y el modo Sprites se vuelve inconsistente. Ahi es donde entran el CONST y el IVARS.

💡 La razon principal del requisito LBDS 1.2.0 La razon principal de que el editor solo pueda usarse en La Base Del Sky 1.2.0 en adelante es la implementacion de Constantes en las UIs de la base, que es exactamente lo que estos modos aprovechan.

7. Modo Const — Trabajando con Constantes

Las constantes no son sprites: no responden a zoom ni cambios de opacidad. Son simples numeros que representan una posicion X o Y.

# Extraido de PokemonPartyPanel — Posiciones de texto e informacion
UI_NAME_X       = 90
UI_NAME_Y       = 22
UI_LEVEL_ICON_X = 20
UI_LEVEL_ICON_Y = 70
UI_LEVEL_TEXT_X = 42
UI_LEVEL_TEXT_Y = 68
UI_GENDER_X     = 230
UI_GENDER_Y     = 22

Dado que los textos dentro del overlay tienen su posicion definida por una constante, al manipular ese numero se puede "mover" el texto. Lo que en realidad se hace es modificar el numero que rige su X/Y.

Controles en Modo Const

  • Constantes _X_: solo se usan ← →
  • Constantes _Y_: solo se usan ↑ ↓

¿Que constantes detecta el editor?

Solo seran detectadas las constantes que contengan alguna de las siguientes palabras clave en su nombre:

_X_YOFFSETPOSWIDTHHEIGHTCENTER

8. Constantes con Hash de Coordenadas

El editor tambien permite trabajar con constantes que almacenen un hash. En este caso los valores son arrays del tipo [x, y] — una matriz 1x2 donde el primer termino es X y el segundo es Y.

# Extraido de PokemonPokedexInfo_Scene
PAGE_INFO_COORDS = {
  :species_name => [246, 48],
  :battled_text => [314, 164],
  :battled_num  => [314, 196],
  :height_text  => [314, 164],
  :weight_text  => [314, 196],
  :category     => [246, 80],
  :height_num   => [470, 164],
  :weight_num   => [482, 196],
}
💡 Requisito de nombre El editor solo aceptara constantes con hash si el nombre incluye: _COORDS

Uso en el codigo

# El indice 0 es x, el indice 1 es y
pbDrawTextPositions(bitmap, [
  TEXT_COORDS[:mi_texto][0],
  TEXT_COORDS[:mi_texto][1],
  ...*args
])

9. Modo IVARS — Variables de Instancia

Las IVARS (variables de instancia) son una manera rapida de hacer lo mismo que con las constantes, pero usando una variable de instancia en lugar de una constante de clase.

💡 Requisito de nombre El editor solo aceptara variables de instancia con contenido numerico si incluyen alguno de estos terminos: _x · _y · _pos · _offset

Comparativa de los tres enfoques

# ✅ Constantes — detectadas por el editor
TEXT_X = 30
TEXT_Y = 90
pbDrawTextPositions(bitmap, [TEXT_X, TEXT_Y, ...*args])

# ✅ Hash de Coordenadas — detectado por el editor
TEXT_COORDS = {
  mi_texto: [30, 90],
  :otro_texto => [30, 90]
}
pbDrawTextPositions(bitmap, [TEXT_COORDS[:mi_texto][0], TEXT_COORDS[:mi_texto][1], ...*args])

# ✅ Variables de instancia — detectadas por el editor
@texto_x = 30
@texto_y = 90
pbDrawTextPositions(bitmap, [@texto_x, @texto_y, ...*args])

# ❌ Variables locales — NO detectadas por el editor
texto_x = 30
texto_y = 90
pbDrawTextPositions(bitmap, [texto_x, texto_y, ...*args])

# ❌ Numeros directos — NO detectados por el editor
pbDrawTextPositions(bitmap, [30, 90, ...*args])
⛔ Evita los "numeros magicos" Pasar coordenadas directamente como numeros literales o usar variables locales hace que el editor no pueda detectarlas ni modificarlas. Usa siempre constantes, hashes o variables de instancia correctamente nombradas.

10. UI Change History — Historial de Cambios

El editor no te obliga a anotar los numeros "a mano". En vez de buscar la posicion final bruta (por ejemplo, x = 256), el editor te dice el delta — la diferencia entre la posicion inicial y la posicion final.

Como acceder al historial

Presiona la tecla K (o la que hayas configurado). Veras dos opciones:

OpcionDescripcion
Ver Delta ActualMuestra la diferencia X/Y del objeto seleccionado actualmente.
Log Total (Consola Debug)Reporte detallado y completo de todos los objetos que tuvieron cambios en la sesion: sprites, constantes e IVARS.

Despues de ver el Log Total, el editor te preguntara si deseas guardar la informacion en un historial. Le daras nombre al cambio y se guardara todo lo que cambio en esa sesion de edicion.

Formatos de archivo disponibles

FormatoContenido
.txtNombre del cambio, fecha, nombre del autor (util si trabajas con multiples personas) e informacion de que constantes, sprites, internals o IVARS cambiaron.
.md (Markdown)Todo lo del .txt, mas una captura de pantalla del antes y despues de como quedo la UI. Hace mas facil saber el resultado sin abrir el juego.
💡 Configuracion del formato Puedes elegir con que formato de archivo trabajar en la configuracion del editor. Por defecto esta en .txt.

11. HUD Principal, Panel de Ayuda y Rejilla de Precision

HUD Principal

El HUD principal es el panel donde se muestran y actualizan en tiempo real las coordenadas y nuevos valores de las propiedades del objeto seleccionado (zoom, z-layer, opacidad, etc.).

  • Presiona F4 para ocultar/mostrar el HUD.
  • Presiona F7 para mover el HUD entre la parte superior e inferior de la pantalla.

Panel de Ayuda

Presiona F5 para mostrar la lista de todos los comandos del editor. Util si te pierdes con alguna tecla mientras editas.

Rejilla de Precision

Activala con la tecla G. Al activarse despliega por toda la pantalla:

  • Lineas rojas: rejilla en multiplos de 8 px (configurable; por defecto en 8).
  • Punto amarillo: representa el punto OX/OY de cada objeto (el punto desde donde rota).
  • Lineas cyan: el "centro" del objeto, calculado segun su bitmap y zoom.

12. Reset Global y Especifico

Si cometes un error o no te gusta el resultado, presiona Backspace (o la tecla que hayas configurado) para abrir el menu de reset:

OpcionDescripcion
Reset GlobalRenueva todas las propiedades del objeto al estado previo a comenzar a editarlo. Solo aplica al objeto seleccionado.
Reset IndividualRenueva una sola propiedad: Posicion (X/Y), Escala (zoom), Opacidad o Angulo. Solo aplica al objeto seleccionado.
Ctrl + ZRevierte un maximo de 50 cambios realizados. Aplica a todos los objetos editados en la sesion.

13. Configuracion del Editor

Al iniciar el editor veras un boton Config. Al accionarlo se mostrara un menu donde puedes personalizar:

OpcionValores disponibles
Formato del archivo de historialtxt · markdown
Tamaño de la rejilla8px · 16px · 32px
Tema de iluminacion del objeto seleccionadoRADIACTIVE (verde radiactivo) · NORMAL (tono normal) · CUSTOM
💡 Sobre el tema CUSTOM Si eliges CUSTOM, tendras que salir y volver a entrar del menu para que carguen los nuevos parametros RGB con los que hayas personalizado el aspecto del objeto seleccionado.
✅ Guardado independiente El editor guarda toda su configuracion en su propio archivo .rxdata, completamente independiente del sistema de guardado del juego.

14. Notas y Buenas Practicas

✅ Usa variables de instancia o hash de coordenadas Para las UIs que crees tu mismo o que vayas a adaptar para el editor, usa variables de instancia o un hash de coordenadas en una Constante. Asi el editor podra detectarlas y modificarlas correctamente.
✅ Nombra tus variables correctamente Usa los sufijos/prefijos reconocidos: _X, _Y, OFFSET, POS, WIDTH, HEIGHT, CENTER, _COORDS, _x, _y, _pos, _offset.
⚠️ Cuidado con los numeros magicos Evita pasar coordenadas como argumentos numericos literales o usar variables locales. El editor no puede detectarlas. Define siempre las posiciones con constantes, hashes o variables de instancia bien nombradas.
⚠️ Internals y el metodo refresh Los cambios hechos a objetos internos se pierden cuando el objeto padre llama a su refresh. Coloca los deltas (+=) al final del refresh o modifica directamente la instancia en la clase del padre.
💡 Tres modos = tres soluciones Sprites, Const e IVARS son tres formas complementarias de editar posiciones. Si el modo Sprites no puede mover algo correctamente (como objetos dentro de un Overlay), usa Const o IVARS para modificar los valores numericos que controlan esa posicion.

Resumen rapido de flujo de trabajo

  1. Instala el plugin y confirma que estas en Modo Debug.
  2. Registra la clase de tu UI en UI_EDITABLE_CLASS dentro de 000_Settings.rb.
  3. Si la UI es personalizada y da problemas, instala manualmente el editor en su ciclo update.
  4. Abre la scene en el juego y presiona F5 para activar el editor.
  5. Usa el Modo Sprite para mover objetos visuales individuales.
  6. Usa el Modo Internals (F) para acceder a objetos hijos.
  7. Usa Const o IVARS cuando el modo Sprite no sea suficiente.
  8. Presiona K para ver el Log y guardar el historial de cambios.
  9. Aplica los deltas reportados en tu codigo fuente.
