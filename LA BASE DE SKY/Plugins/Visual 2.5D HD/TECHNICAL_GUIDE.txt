================================================================================
1. QUÉ HACE EL PLUGIN (resumen)
================================================================================

El plugin NO cambia la jugabilidad. Toma el mapa 2D existente de Pokémon
Essentials y lo proyecta en perspectiva (efecto 2.5D / tilt-shift / maqueta).

Dos transformaciones principales:

  A) SUELO (prioridad 0)
     Cada fila del tilemap se escala y reposiciona según la inclinación de
     cámara y el zoom. Todas las filas comparten la misma función de proyección,
     así que no hay cortes entre tiles vecinos. GROUND_SLICES (default 2)
     parte cada tile de suelo en franjas para seguir la curva del punto de
     fuga. Si la fila tiene un tile transparente (cuerpo con alpha, autotile
     de agua, o casilla can_surf), la fila ENTERA va en un solo trapecio.
     Partir solo ese tile y dejar el vecino en mitades abre un hueco en la
     junta (raya negra, canto roto). No se usa el brillo del borde: eso
     pillaba la montaña. El sellado de los muros no cambia.

  B) ELEMENTOS VERTICALES (prioridad > 0)
     Los tiles con prioridad se "ponen de pie" sobre su casilla de apoyo (la
     casilla que está N filas más abajo, donde N = prioridad). Las columnas
     enteras comparten la misma base y salen rectas.

  C) PAREDES FRONTALES (terrain tag :Cliff, id 19)
     Tiles marcados con el tag de acantilado se levantan como bordillos aunque
     tengan prioridad 0. Sistema independiente del de prioridades.

  D) PAREDES INTERIORES (terrain tag :InteriorWall, id 20)
     Casilla sin cuerpo pri (borde top-down de pasillo). En 2.5D: tapa plana
     arriba + columna rellenada con bandas de geometria de tile pri (arista sur,
     row_unit, ancho de un tile), textura de la pila de la esquina. En 2D: tile
     del editor, sin bandas.

  E) TECHO SHELF (terrain tag :Shelf, id 21)
     El 21 solo marca "tumbado" (esa capa). La cota es la prioridad del tile:
     se dibuja plano en la BASE de esa altura (canto bajo del vertical).
     pri 1+21 = ras de suelo; pri 5+21 = cierra con el vertical pri 4.
     InteriorWall (20) sigue siendo tapa-columna.

  F) PERSONAJES Y SPRITES AUXILIARES
     Se proyectan con las mismas funciones que el suelo, con un factor de
     levantamiento reducido (CHARACTER_GAIN) para que no queden tapados por tiles
     de la fila superior. El tag 21 no mueve al personaje.

  G) ATMÓSFERA
     Neblina superior, neblina de primer plano y viñeta — overlays decorativos
     que refuerzan la sensación de profundidad / maqueta.

2. ORDEN DE CARGA DE ARCHIVOS
================================================================================

Los scripts se cargan por prefijo numérico. El orden importa:

  [001] Settings.rb          → Constantes Config (sin lógica)
  [002] Core.rb              → Módulo Visual25D: proyección, márgenes, estado
  [003] Tile Depth.rb        → Hooks en TilemapRenderer (tiles nativos)
  [004] Character Depth.rb   → Hooks en Game_Character y Sprite_Character
  [006] Atmosphere.rb        → Overlays + hooks en Scene_Map
  [007] Debug Menu.rb        → Menús de depuración y herramientas de diagnóstico
  [008] Options.rb           → Persistencia en partida + opción en menú gráficos
  [009] Auxiliary Sprites.rb → ScreenPosHelper, huellas, culling extendido
  [010] Front Walls.rb       → Sistema de paredes frontales (WallField)
  [011] Interior Walls.rb    → Tag InteriorWall + billboards 2.5D-only
  [012] MakerStudio Bridge.rb→ Integración con MakerStudio (condicional)
  [013] Darkness Bridge.rb   → Oscuridad Dinamica: luces en coords 2.5D
  [014] Shelf Tiles.rb       → Tag Shelf: tapa tumbada a la base de su pri
  [015] Diorama.rb           → Fila de suelo, sombra de contacto, toggles

meta.txt: Last=true + Optional=MakerStudio / Caruban's Dynamic Darkness.
  No editar MakerStudio: solo alias en [012] MakerStudio Bridge.rb.

Dependencias externas:
  - Pokémon Essentials 21.1 (TilemapRenderer, Scene_Map, PokemonSystem, etc.)
  - MakerStudio (opcional): capas extendidas y sombras
  - FootprintsSettings (opcional): huellas en arena

3. ARQUITECTURA Y FLUJO POR FRAME
================================================================================

Scene_Map#updateSpritesets (cada frame)
  │
  ├─ Visual25D.refresh_active
  │    ├─ sync_with_save (solo si dirty: carga, F12, opciones)
  │    ├─ Comprueba DISABLE_SWITCH
  │    └─ flush_refresh → map_renderer.refresh si hay cambios pendientes
  │
  ├─ Sprite_Character#update → hd25_apply_depth (zoom; cache por pose/encuadre)
  │
  ├─ TilemapRenderer#update (envuelto en hd25_engine_update)
  │    ├─ hd25_sync_grid (amplía/restringe rejilla según márgenes)
  │    ├─ Visual25D.shift_maps_for_render (corre display_x/y temporalmente)
  │    ├─ prime_map_offsets! (dirty-cache por display/mapas)
  │    ├─ update nativo del motor
  │    │    ├─ check_if_screen_moved → update_projection UNA vez (tabla filas)
  │    │    └─ por tile: refresh_tile / coordinates → project_tile
  │    │       (MS refresh_tile: defer_tile_project → 1 project al final)
  │    └─ Visual25D.restore_maps_after_render (ensure)
  │
  ├─ MakerStudio: update_extended_pool → project_ext_sprite (si activo)
  │
  ├─ @hd25_atmosphere.update (early-out si enabled/outdoor/opacidad/tone igual)
  └─ @hd25_interior_walls.update (select por celda; place por display/stamp)

Al crear spritesets (Scene_Map#createSpritesets):
  └─ Visual25D.reset_render_state (limpia @shifted_maps tras F12)

Rendimiento (mismo look):
  - update_projection no se llama por tile; una vez tras pixel_offset final.
  - prime_map_offsets! reutiliza cache si display/mapas no cambiaron.
  - InteriorWalls no hace select/place en idle.
  - v3.2.14: tiles cuya caja proyectada no corta la pantalla se ocultan una
    vez (cull/f en el probe) y no se vuelven a mover hasta que entran.
    Alturas de InteriorWall se resuelven al escanear, no cada frame.
  - v3.3.0: curva de horizonte (HORIZON_CURVE, 14). Opciones gráficas
    "Mundo 2.5D": Redondo (14) o Plano (0). También pbVisual25DMundoRedondo.
    ROW_BATCH y BAND_BLUR van en false.

4. MÓDULO CENTRAL: Visual25D (Core.rb)
================================================================================

Namespace: module Visual25D
Config:    module Visual25D::Config (definido en [001] Settings.rb)

--- Estado ---

  enabled / enabled=     Estado deseado por jugador/dev (@wanted)
  enabled?               Estado real del frame (@active), respeta DISABLE_SWITCH
  tilt / tilt=           Inclinación cámara en grados (0 = vista cenital)
  camera_zoom / camera_zoom=  Zoom en % (100 = original, <100 = más lejos)
  tile_lift / tile_lift= Exageración extra de altura por nivel de prioridad
  perspective            tan(tilt) — derivado, no tocar directamente
  haze_opacity, near_haze_opacity, vignette_opacity

  reset_to_defaults      Restaura todo a Config
  reset_render_state     Limpia corrimientos de mapa y proyección (post-F12)
  redraw_map / flush_refresh  Fuerza recálculo y refresh del renderer

--- Proyección (funciones clave) ---

  scale_at(y)            Escala en profundidad para la fila de pantalla y
  width_scale_at(y)      Escala en anchura (converge menos → VANISHING_STRENGTH)
  project_y(y)           Posición Y proyectada (integral de scale_at)
  project_x(x, scale)    Posición X proyectada alrededor del centro de pantalla
  shape_at(y)            Perfil de perspectiva normalizado
  update_projection(pixel_offset_y)  Precalcula tablas @row_top, @row_width, @row_unit
  row_at(unprojected_y)  Fila de rejilla para coordenada sin proyectar
  row_top(row), row_width_scale(row), row_unit(row), row_step(row), step_at(y)

  vertical_gain          Factor de "ponerse de pie" según inclinación
  vertical_unit_at(y)    Altura de un tramo vertical de 1 tile
  character_unit_at(y)   Altura de personaje (menor que vertical_unit_at)
  projected_height(h, ground)  Altura de sprite en mundo proyectado

--- Z-ordering ---

  Z_LIFT                 Desplazamiento global para que nada quede bajo el suelo
  raised_tile?(tile)     Overhead para Z (cell_band>0 si MS; si no priority>0)
  geom_raised?(tile)     Geometria WallField (prioridad pintada / hd25_geom_priority)
  geom_priority(tile)    Prioridad pintada propia (nunca cell_band)
  raised_tile_z(z)       Z para tiles levantados (solo si raised_tile?)
  character_z(z, ground) Z para personajes (+ TILE_CLEARANCE si apoyado en casilla)
  always_on_top_z        Z del flag Always on Top (999 nativo < tiles raised)

--- Rejilla ampliada ---

  margin_columns, margin_rows     Casillas extra en la rejilla del tilemap
  margin_offset_x, margin_offset_y  Píxeles de offset del margen
  shift_maps_for_render / restore_maps_after_render  Corrimiento temporal de display
  map_in_range?(dispx, dispy, w, h)  Rango extendido para mapas conectados

--- Texturas generadas ---

  haze_bitmap(:top|:bottom), vignette_bitmap(edge), vignette_size

--- [011] Interior Walls.rb ---
  Registra GameData::TerrainTag :InteriorWall (id_number 20).

  LO QUE HAY QUE ENTENDER ANTES DE TOCAR ESTO (medido, tilt 50 / zoom 90):
  - wall_column_feet_y: un tile pri p apoya en la arista sur de la fila cy+p (p
    filas al SUR) y luego sube p*unit. unit = 36.6 px y la fila mide 32.7 px, o
    sea que un pri 4 acaba ~16 px por encima de su propia fila. Las paredes se
    dibujan EN SU SITIO con exageracion pequena; no son torres.
  - Divergencia horizontal de lo elevado: 0.0147 de escala por fila
    (VANISHING_STRENGTH 0.3, bajo a proposito) → ~1 px por nivel a dos casillas.
  => Una cara que mira al este/oeste queda de canto: 3 px de ancho, 16 px de
     alto. NO se puede derivar de la proyeccion. Cualquier cara lateral visible
     es una estilizacion decidida. Historial: intentar derivarla dio dominos,
     placas de frente y pelos de 1 px (v3.1.x, 3.2.0, 3.2.1).

  MODELO v3.2.2 (tapa alineada + GROSOR falso):
  Tapa: project_interior_cap dibuja el tile como si tuviera prioridad h
  (raised_width_row + wall_column_feet_y), asi que queda a la misma cota y
  escala que la cima de la masa vecina.

  Grosor: 1 sprite por casilla y lado expuesto, en la MISMA banda vertical que
  la tapa (por eso acaba a la cota de la masa):
    x_row  = row + h - 1 ; unit = row_unit(x_row) ; scale = row_width_scale(x_row)
    feet   = wall_column_feet_y(walls, cx, cy, row, h)
    top    = feet - h*unit
    bottom = max(feet - (h-1)*unit, top de la casilla siguiente) + WALL_EDGE_SEAL
    ancho  = (INTERIOR_SIDE_WIDTH * scale), anclado en el canto del hueco y
             creciendo hacia DENTRO del muro (nunca invade el pasillo)
    z      = raised_tile_z(((row + h + 1) * tile_h) - poy + 1) + 1  # sobre la tapa
  El bottom contra la casilla siguiente es lo que hace el tramo continuo: la
  banda mide unit pero el paso entre filas es el spacing de la fila, y en primer
  plano spacing > unit (medido: solape +12 px arriba de pantalla, -6 px abajo).
  Sin ese estirado salen cortes negros cada fila = los "dominos".
  run_end (ultima casilla del tramo al sur) baja la franja hasta el suelo para
  cerrar la esquina con la pared de frente.
  Textura = una bitmap apilada (zocalo abajo, remate arriba), recortada al canto
  (src_rect). El ancho no se aplasta; el alto de la pila se reparte en la franja.

  Altura: Visual25D.interior_wall_height(map, cx, cy) en [003] — max pri del
  cuerpo vecino (tope MAX_PRIORITY), fallback INTERIOR_WALL_HEIGHT. La usan la
  tapa y las bandas, asi que acaban a la misma cota (mapa 196: masa pri 4).

  Textura por nivel = pila de la esquina: cuerpo pri contiguo en la misma
  columna hacia el sur (196: tag 20 en (37,27..42) → (37,43..45) pri 3/2/1).
  Banda 1 = pri mas bajo (zocalo), banda H = pri mas alto (remate), medias con
  el panel intermedio. Sin pila → INTERIOR_WALL_FALLBACK.

  Visual25D::InteriorWallField — Cell(x, y, dirs, height, levels, run_end)
    dirs = lados con hueco (:E/:W); sin hueco lateral la casilla es solo tapa.
    Pila de textura resuelta 1 vez por tramo contiguo N-S, no por casilla.
  Visual25D::InteriorWallLayer — pool de franjas (1 sprite por lado/casilla),
    culling VIEW_RADIUS, firmas casilla (set) vs display/stamp (place).

  Visual25D:
    interior_wall_field(map)  Cache por map_id
    clear_interior_faces      Invalida en Game_Map#setup y en Core (row table)

6. CONCEPTOS CLAVE PARA MODIFICAR SIN ROMPER NADA
================================================================================

--- Prioridad de tiles (0..MAX_PRIORITY, default 12; MS puede >5) ---
  prioridad 0 = suelo plano
  prioridad N = elemento vertical de N tiles de alto; casilla de apoyo = N filas abajo
  Numerar de abajo arriba: base=1, encima=2, etc. NO dejar base en 0 si la copa tiene prioridad.
  Si N > MAX_PRIORITY → se trata como MAX_PRIORITY (cortes / Z mal).

--- Punto de fuga ---
  Sale de project_x con width_scale_at. VANISHING_STRENGTH controla convergencia lateral.
  Valores altos (>0.4) despegan elementos altos de su casilla.

--- Rejilla ampliada ---
  Al alejar/inclinar la cámara, el motor reserva pocas casillas. El plugin:
    1. Aumenta @tiles_horizontal/vertical_count
    2. Suma margen a @pixel_offset_x/y
    3. Corrige display_x/y de todos los mapas durante el render
  MAX_MARGIN_* limita el coste de rendimiento.

--- Z-ordering ---
  Problema resuelto: filas fuera de pantalla daban Z negativa y parpadeaban.
  Solución: Z_LIFT desplaza todo lo "de pie" por encima del suelo.
  Personajes llevan TILE_CLEARANCE extra para quedar delante de tiles de su casilla.
  project_tile_z USA espacio plano ((row+pri+1)*H - offset), igual que screen_z /
  ms_overhead_tile_z. NO usar Y proyectada (wall_column_anchor_y): con Cliff en el
  mapa el jugador quedaba siempre delante de los tiles con prioridad.

--- Patrón alias F12 ---
  SIEMPRE: alias dentro de `unless method_defined?`, redefinición fuera.
  Si se mete la redefinición dentro de la guarda, tras F12 algunos hooks sobreviven
  y otros no → mapas desplazados permanentemente.

--- Integración con otros plugins de mapas ---
  MakerStudio reescribe Z y posición. Este plugin:
    - Aplica Z en tile.z= (setter) no solo refresh_tile_z
    - Absorbe margen en check_if_screen_moved
    - Multiplica hd25_base_zoom_x/y en vez de pisar zoom de efectos

--- cell_band vs geometria (v3.0.3) ---
  cell_band = solo overhead vs ground-cap MakerStudio (no altura de columna).
  Geometria + Z de columna = hd25_painted_priority / hd25_geom_priority.
  pri>0 bajo ground-cap: band=0 pero geom>0 → billboard + Z de columna.
  Capas extended: project_ext_sprite reafirma geom cada frame.
  2.5D OFF: margen 0 + restore_ext_sprite_2d (zoom/Z suelo). Cap-model MS intacto.

8. MAPAS Y TILESETS — REGLAS DE DISEÑO
================================================================================

  1. Paredes frontales: marcar con terrain tag :Cliff (19) solo la cara que
     mira a la cámara (terreno alto arriba, bajo abajo). No marcar laterales.

  2. Paredes interiores: marcar con :InteriorWall (20) el borde/tapa del muro.
     En 2.5D → tapa plana + columna de bandas hasta la cota del cuerpo vecino.
     Conviene que la masa de al lado tenga su prioridad real (marca la altura) y
     que la columna tenga pila de frente al sur (pri 1..3 = textura).
     Casilla rodeada de cuerpo pri: no se dibuja (no se ve).

  3. Elementos verticales: prioridad = altura en tiles. Base mínima = 1.

  3b. Techo / meseta: tag 21 en la CAPA del techo + prioridad P.
      Se tumba en la base de P (cierra con el vertical P-1). Cara sur
      pri 1..(P-1) sin 21. pri 1+21 = ras de suelo. Z = P.

  3c. Eventos a una cota: nombre con [hN] (ej. Farol [h5]). Se coloca como el
      siguiente tramo de la columna (encima de pri 1..N-1 al sur), no flotando
      N tiles sobre su casilla. Mejor: evento en la casilla donde iría el tile
      pri N. Si lo pones EN la cima (pri N-1), también se detecta y sube un tramo.

  4. Bordillos de 2 tiles: marcar ambos. Columnas de 3+ = dos bordillos si los
     tramos horizontales no se solapan.

  5. Casillas sin tile en ninguna capa → se ven negras (pbVisual25DFindGaps).

  6. Huecos entre filas → proyección incorrecta o falta de tile (pbVisual25DFindGaps).

  7. Mapas sin conexiones + cámara muy alejada → se ve vacío al borde (esperado).

14. mkxp-z-ext / Model3D — por qué no se usa en runtime
================================================================================

Repo: https://github.com/luka-sj/mkxp-z-ext
Rama: feature.3d-object-support (PR #7; diverged de dev, no mergeada).

Ese fork añade clase C++ Model3D (OBJ→FBO+depth→Bitmap) y CustomShader.
Solo existe si compilas/usas ese Game.exe. El ejecutable estándar sin extensiones 3D no incluye esa función.

Visual 2.5D HD es fake-3D Ruby (tiles + proyección por fila). Del fork solo
se tomaron ideas baratas:
  - FOV/profundidad → Config::PROJECTION_MODEL = :camera
  - light/ambient → Config::LIGHT_BIAS en Atmosphere

raw_unproject (márgenes / y_shift) soporta classic y camera desde v3.0.39.
Menú debug puede cambiar modelo/FOV en sesión (no se guarda en partida).

Bake de props 3D → PNG: herramienta externa (Blender), no runtime.
